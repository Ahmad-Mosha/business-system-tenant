# Arabic and English — how the frontend speaks both

Prime Market's web app runs in Arabic (the default for first-time visitors) and
English. This is the foundation every screen builds on; screens move onto it
module by module.

## Where the language comes from

- **A cookie, `NEXT_LOCALE`** (`ar` / `en`), set by the language switcher — in
  the user menu, and on the sign-in screen. This browser only; there is no
  account setting, by decision (2026-09-14).
- `src/i18n/config.ts` holds the languages and what follows from each;
  `src/i18n/request.ts` reads the cookie for every request (next-intl, no
  locale in the URL — every route and link stays as it is).
- The root layout sets `<html lang dir>` and wraps the app in next-intl's
  provider and Radix's `DirectionProvider`. Nothing else checks the language to
  lay itself out.

## Words: `src/messages/{en,ar}.json`

- English is the source of truth. Keys are type-checked (`src/i18n/types.d.ts`)
  and `src/i18n/messages.test.ts` fails if Arabic misses a key or a placeholder.
- Server components: `const t = await getTranslations('ns')`. Client and plain
  components: `const t = useTranslations('ns')`. Server actions use
  `getTranslations` too (see `app/login/actions.ts`).
- **Counts are ICU plurals.** Arabic has six forms — never `${n} items`:
  `"{count, plural, =0 {لا توجد طلبات} one {طلب واحد} two {طلبان} few {# طلبات} many {# طلبًا} other {# طلب}}"`.
- **Statuses and types live in `enums.*`**, keyed by the API's value
  (`enums.orderStatus.DELIVERED`). Tones stay in code; names come from messages.
- **Not translated — business data:** product and customer names, SKUs, noon
  partner / Amazon seller SKUs, order and tracking numbers, supplier names,
  notes people type, governorates (Bosta's Arabic names). Bilingual reference
  data the API sends (ledger accounts' `nameAr` / `nameEn`) is picked by
  language, not translated.
- `react/jsx-no-literals` warns on text in JSX. It turns into an error once
  every screen has moved over.

## Direction

- `components.json` has `"rtl": true`: shadcn components are added — and were
  migrated (`shadcn migrate rtl`) — with logical classes. Write `ms- me- ps- pe-
  start- end- text-start text-end border-s border-e`, never `ml- pr- left- text-right`.
- **Icons:** arrows and chevrons that mean *forward/back* flip —
  `rtl:rotate-180` for horizontal ones, `rtl:-scale-x-100` for diagonals (a
  rotation would turn ↗ into ↙). Trend arrows (up/down) don't.
- **Sheets** take `side="start" | "end"` (default `end`, the reading end). The
  sidebar's sides are logical too: it sits on the right in Arabic.
- **Mixed text:** `<bdi>` around data inside a sentence; `Amount` isolates
  figures left-to-right so a minus never jumps sides. An Arabic range reads
  "1 إلى 20", not "1–20" (the dash reverses in RTL).

## Numbers, dates, money

- Locales `ar-EG-u-nu-latn` and `en-GB`: Egyptian Arabic month names and ج.م,
  **Western digits in both** (decision 2026-09-14), day-first English.
- Every date/time is in **Cairo time** (`Africa/Cairo`), whatever zone the
  server runs in. Things recorded from a date alone print without a time.
- `getFormat()` (async server) / `useFormat()` (everything else) —
  `src/i18n/format.ts`: `date`, `dateTime`, `time`, `day` ("Today" / "اليوم"),
  `month`, `count`, `compact` ("1.3 مليون"), `byDay`.
- Money reads identically in both languages (`1,234,567.50`), so `money()` and
  `Amount` stay in `lib/`; the currency label is `common.egp` (EGP · ج.م).

## Charts

Geometry is always laid out left to right (Recharts assumes it); each chart
mirrors by kind, not blanket: **time series keep time left→right** — the most
common pattern in Arabic charts (IEEE VIS 2024) and the way digits read;
**breakdowns mirror** — label at the reading start, bar growing leftward.
Ticks, tooltips and legends are in the reader's language; tooltips read RTL.

## Arabic copy

Business Arabic, not a literal translation. Terms the team already uses win:

| English | Arabic |
|---|---|
| Treasury | الخزينة |
| Ledger · account statement | سجل الحركات · كشف الحساب |
| Inventory | المخزون |
| Sales | المبيعات |
| Supplier payable | مستحقات الموردين |
| Receipt voucher · Payment voucher | سند قبض · سند صرف |
| Cash deposit · Cheque deposit | إيداع نقدي · إيداع سندي |
| Purchase invoice | فاتورة شراء |
| Owner withdrawal | مسحوبات المالك |
| Out of stock · Low stock | نفد من المخزون · مخزون منخفض |
| Social (channel) | السوشيال ميديا |

Letter-spacing is off for Arabic text (it breaks the joins) — `globals.css`.
