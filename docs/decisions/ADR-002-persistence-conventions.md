# ADR-002: Postgres, Drizzle, and core data conventions

**Status:** Accepted · 2026-08-18

## Context

This system's value is that its numbers can be trusted and explained. The data layer has
to make correctness the default and drift hard to introduce.

## Decision

PostgreSQL with Drizzle, and five conventions applied everywhere.

### Postgres, one instance

Transactions, `numeric`, `jsonb` for raw provider payloads, window functions for ledger
queries. Nothing in this system needs anything else, and at hundreds of orders a day it
will not for years.

### Drizzle over Prisma

SQL-first, which suits the aggregation and ledger work that is coming; migrations are
plain SQL files, reviewable in a pull request. Prisma is more ergonomic for CRUD but
fights back on complex reporting queries. Low-risk either way.

No repository layer over the ORM. Services query directly. Repositories will be
introduced only around the stock and money ledgers, where invariants justify them.

### UUIDv7 identifiers, generated by the application

Time-ordered, so index inserts stay local; no sequence to enumerate, so ids are safe to
expose; and generating them in the application means an entity can be referenced before
it is inserted.

**Its leading characters are a timestamp and are therefore not unique.** Slicing the
front of a UUIDv7 to build a "unique" value collides within the same millisecond - this
was caught by a failing test, not in review.

### Money as `bigint` minor units plus an explicit currency

Floating point cannot represent currency, and a bare number with an assumed currency is
a bug waiting for the second market. Conversion to a decimal happens once, at the UI.

### `timestamptz` stored UTC, rendered Africa/Cairo

A "daily sales" figure is meaningless without a stated day boundary.

### `organization_id` on every business table

Costs a column now. Retrofitting it into a live financial database is a multi-week
migration where one missed filter leaks one customer's finances to another.

## Trade-offs accepted

Drizzle's ecosystem is smaller than Prisma's. Minor units mean every read and write site
must respect the unit - enforced by the shared `Money` contract type.
